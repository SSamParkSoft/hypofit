## 1. Objective

Replace the current Hypofit logo and icon family with the newly approved
geometric mark and apply one coherent identity across web, PWA, iOS, Android,
splash, notification, sharing, and store-upload surfaces.

The implementation must produce a repeatable asset system rather than a
collection of manually resized PNG files:

```text
approved geometric source
  -> clean vector master
  -> platform-specific compositions
  -> deterministic exports
  -> code/config integration
  -> device, browser, and store QA
```

The migration is complete only when:

- the old speech-bubble/checkmark mark no longer appears in a current product
  or release surface,
- all raster outputs can be regenerated from the same approved vector geometry,
- iOS, Android, PWA, favicon, splash, notification, and store icons each follow
  their platform's masking and alpha rules,
- old service-worker and installed-app caches cannot leave users with a mixed
  old/new identity,
- the final approved asset family is documented.

## 2. Approved Visual Input

Current source reference:

```text
docs/store-assets/brand/source/hypofit-fit-node-reference.png
```

Observed source properties:

- PNG,
- `1254 x 1254`,
- RGB without transparency,
- deep teal square background,
- two symmetric warm-white geometric forms,
- one amber circular signal centered between the forms,
- subtle raster gradients, edge softness, and shadows generated by the image
  model.

The approved identity concept is the geometry, not every raster artifact in the
generated PNG.

Interpretation:

- the left and right forms represent founder and target customer,
- the central amber point represents the real customer signal being found,
- the negative space communicates fit, alignment, and a focused interview
  connection,
- the overall silhouette can also be read as a restrained `H`,
- no speech bubble, checkmark, survey sheet, magnifying glass, or generic AI
  sparkle is needed.

Working name inside design and implementation discussions:

```text
Fit Node
```

This is an internal concept name, not user-facing product copy.

## 3. Decisions To Lock Before Export

### 3.1 Geometry Is Approved, Raster Treatment Is Not The Master

Do not use the Desktop PNG as the permanent production master.

Create a vector reconstruction with:

- exact bilateral symmetry,
- clean curves and straight segments,
- optically centered amber node,
- consistent corner radii,
- no baked-in drop shadow,
- no soft or feathered path edges,
- no hidden background pixels,
- no image-model texture or compression artifacts.

The approved PNG is already archived under the store-asset source folder and
should remain a visual reference only.

### 3.2 Preserve The Existing Product Color Contract

The generated image's dominant teal is visually close to `#0C645B`, while the
current canonical Hypofit brand token is `#176B5D`.

Default implementation decision:

- retain `#176B5D` as the canonical Hypofit brand green,
- use `#0F4F44` only where a stronger brand tone is already required,
- use a warm white close to the product backgrounds, initially `#F7F5EF`,
- introduce one controlled amber signal color, initially `#F5A623`,
- keep the amber as a brand accent, not as a success, warning, payment, or
  application-status semantic color.

This migration must not silently recolor the entire UI to the generated
`#0C645B`.

If the team explicitly prefers the generated teal after side-by-side review,
that becomes a separate design-token migration with contrast, screenshot,
store-asset, and visual-regression impact. It must not be hidden inside an icon
replacement commit.

### 3.3 One Shape, Platform-Specific Compositions

The core Fit Node geometry remains stable, but every surface does not use the
same crop:

- in-product brand mark: transparent, tightly bounded geometry,
- horizontal wordmark: mark plus `Hypofit`,
- iOS icon: opaque, full square, no pre-rounded corners,
- Android adaptive icon: transparent foreground plus independent background,
- Android monochrome icon: one-color silhouette,
- Android notification icon: one-color alpha mask with no amber fill,
- favicon: optically enlarged and simplified small-size mark,
- PWA maskable icon: additional safe-zone padding,
- splash: transparent mark over the native splash background,
- store icon: store-specific 512 or 1024 export, not a random resize of a
  screenshot.

### 3.4 Wordmark Remains Accessible Text In Product UI

Where the app or web UI currently renders an icon beside `Hypofit`, keep the
brand name as live text when practical:

- it stays sharp at every scale,
- it follows the app font,
- it remains accessible and localizable,
- the icon can be marked decorative when adjacent text already names the brand.

The horizontal logo SVG is for public brand, documentation, store creative, and
places that need a fixed lockup. Do not replace every live `Hypofit` label with
an image.

```text
    export/

```

Deterministic export tooling:

```text
apps/web/scripts/export-brand-assets.mjs
```

The export script should:

- read the canonical SVG sources,
- fail if expected source files are missing,
- generate PNG outputs at declared dimensions,
- preserve or remove alpha according to each target,
- generate favicon PNGs and ICO,

  `pnpm brand:export`.

Use a small, established SVG-to-raster tool such as `sharp` and an ICO encoder
only if the repository does not already contain an equivalent. Do not introduce
a full design pipeline or remote rendering service for this bounded job.

## 5. Master Logo Variants

### 5.1 Full-Color Mark

Purpose:

- in-product headers,
- auth and splash branding,
- public landing and support pages,
- profile and shell branding,
- general brand reference.

Properties:

- transparent background,
- brand-green outer forms,
- amber center node,
- no shadow,
- no rounded square container,
- tight vector `viewBox`,
- SVG source plus 1x/2x raster preview.

### 5.2 Inverse Mark

Purpose:

- green native splash background,
- dark brand bands,
- dark marketing backgrounds.

Properties:

- warm-white outer forms,
- amber center node,
- transparent background,
- no outer square.

### 5.3 Monochrome Mark

Purpose:

- Android themed icon,
- Android notification icon source,
- one-color print or legal contexts,
- high-contrast fallback.

Properties:

- one merged foreground color,
- transparent background,
- central node represented through silhouette or negative space rather than a
  second color,
- remains recognizable at `24 px`.

### 5.4 Small Optical Mark

Purpose:

- favicon,
- compact browser chrome,
- very small navigation or metadata surfaces.

Adjustments allowed:

- slightly enlarge the amber node,
- slightly widen the central negative space,
- simplify tight curvature,
- increase outer-form separation,
- remove all nonessential shading.

The small mark must retain the same identity, not become a separate symbol.

### 5.5 Horizontal Wordmark

Composition:

```text
[Fit Node mark] Hypofit
```

Rules:

- use Spoqa Han Sans Neo Bold or a reviewed custom outlined wordmark,
- use zero negative letter spacing,
- preserve a calm, modern weight,
- keep the mark and wordmark vertically optically aligned,
- provide default, inverse, and monochrome forms,
- do not include a slogan in the logo file.

### 5.6 App Icon Composition

Properties:

- brand-green full-bleed background,
- centered warm-white Fit Node forms,
- amber center node,
- no text,
- no checkmark,
- no pre-rendered rounded corners,
- no device-frame shadow,
- strong silhouette at `29 px`, `40 px`, and `60 px`.

The mark size should be tuned separately from the tight product mark. Initial
review range:

- artwork width approximately `61%` to `66%` of the square,
- enough margin for iOS masking and Android launcher effects,
- central node large enough to remain visible in Settings and search results.

- exactly square,
- full-bleed opaque app icon,
- no transparent corner pixels,
- no manually rounded mask,
- verify at `1024`, `180`, `120`, `87`, `60`, `40`, and `29 px` preview sizes.

Dark, clear, and tinted iOS appearance work is a later enhancement unless the
current Expo configuration can provide it without an SDK migration. The

### 6.4 Expo Android Assets

| Output | Size | Alpha | Purpose |
| --- | --- | --- | --- |
| `apps/mobile/assets/icon.png` | `1024 x 1024` | no | legacy launcher fallback |
| `apps/mobile/assets/adaptive-icon.png` | `1024 x 1024` | yes | adaptive foreground |
| `apps/mobile/assets/adaptive-icon-monochrome.png` | `1024 x 1024` | yes | themed icon layer |
| `apps/mobile/assets/notification-icon.png` | `96 x 96` or Expo-required density source | yes | status notification glyph |

Adaptive-icon geometry:

- design each conceptual layer on a `108 x 108 dp` canvas,
- keep the essential mark within the centered `66 x 66 dp` safe zone,
- reserve the outer `18 dp` on each side for masking and motion,
- use clean edges,
- do not bake a mask or outer shadow into the foreground,
- test circle, squircle, rounded square, and OEM masks,
- configure `android.adaptiveIcon.monochromeImage` in `app.config.ts`.

Notification icon:

- pure white foreground information in the source alpha mask,
- transparent background,
- no amber or multicolor dependence,
- no rounded square container,
- legible in status bar and notification shade,
- distinct from the full launcher icon.

### 6.5 Store Upload Assets

Apple:

```text
docs/store-assets/brand/export/apple/hypofit-app-icon-1024.png
```

This file is the reviewed release artifact and binary input reference. For the
normal iOS app flow, App Store Connect receives the app icon from the uploaded
build and does not require a second manual icon upload.

Requirements:

- `1024 x 1024`,
- opaque,
- sRGB,
- no rounded corners,
- same identity as the app binary icon.

Google Play:

```text
docs/store-assets/brand/export/google-play/hypofit-play-icon-512.png
```

Requirements:

- `512 x 512`,
- 32-bit PNG with alpha channel support,
- at most `1024 KB`,
- no ranking, price, category, sale, or store badge text,
- no Google Play-applied rounded corner or shadow baked into the artwork,
- visually consistent with the Android launcher icon.

The Play listing icon and Android launcher icon are related exports, not the
same file copied blindly. The listing icon can use store-specific optical
sizing while preserving identical geometry and palette.

Composition:

- `1200 x 630`,

Update `apps/web/index.html` only after the image exists and is reviewed.

### 7.2 Web Cache Migration

The current service worker caches `/icons/icon.svg` under
`hypofit-shell-v1`.

During implementation:

- bump the cache namespace,
- remove the previous cache during activation,
- verify the new manifest and icon files are returned after reload,
- verify an already installed PWA updates rather than retaining the old icon,
- document that operating systems can retain home-screen icon caches until
  reinstall,
- use a temporary query version in HTML only if browser favicon caching remains
  observable after the service-worker update.

Do not rename every public asset solely to avoid cache invalidation. Use the
existing cache lifecycle first.

### 7.3 Mobile Code And Config

Review and update:

- `apps/mobile/app.config.ts`
- `apps/mobile/src/screens/auth/SplashScreen.tsx`
- `apps/mobile/src/screens/auth/AuthScreenFrame.tsx`
- `apps/mobile/src/screens/home/HomeScreen.tsx`
- `apps/mobile/docs/parity-checklist.md`

Configuration changes:

- keep `icon` pointed to the new opaque `icon.png`,
- keep Android adaptive foreground separate from its background color,
- add `monochromeImage`,
- keep notification color aligned to canonical brand green,
- point the native splash plugin at the reviewed transparent splash mark,
- verify `imageWidth` optically rather than preserving `320` by habit,
- preserve the current native-splash-to-RN-splash continuity.

The native icon and splash are binary resources. Metro reload or OTA JavaScript
updates are insufficient. A new native build and reinstall are required.

### 7.4 Splash Continuity

The launch sequence must read as one continuous brand moment:

```text
native splash
  -> RN startup splash
  -> authenticated home or auth screen
```

Rules:

- use the same inverse mark geometry in native and RN splash,
- use the same background green,
- keep native splash static,
- begin progress animation only after the RN layer is mounted,
- do not introduce a second scale jump or mark-position jump,
- test in a production or preview build because Expo Go and development builds
  can display their own launch behavior.

## 8. Optical And Brand QA

### 8.1 Geometry Review

Check:

- bilateral symmetry,
- equal visual mass on the left and right,
- node centered geometrically and optically,
- corner radii consistent,
- no accidental narrow gaps,
- no raster seams,
- no leftover checkmark or speech-bubble geometry,
- recognizable silhouette without the amber color.

### 8.2 Small-Size Review

Render the mark at:

```text
16, 24, 29, 32, 40, 48, 60, 87, 120, 180, 192, 512, 1024 px
```

Acceptance:

- central node is not lost,
- two outer forms do not merge,
- the mark does not look like a pause icon, butterfly, dumbbell, or unrelated
  category symbol,
- favicon remains recognizable beside browser tabs,
- notification silhouette remains legible without color.

### 8.3 Background Review

Preview on:

- white,
- `#F6F7F8`,
- brand green,
- black,
- light and dark photo backgrounds,
- representative iOS and Android wallpapers.

No production mark may depend on an invisible light edge or subtle shadow to
separate itself from the background.

### 8.4 Mask Review

Preview the app icon under:

- iOS rounded-square masking,
- Android circle,
- Android squircle,
- Android rounded square,
- aggressive OEM mask,
- Android themed monochrome mode.

No essential point, curve, or amber node may enter a clipped region.

### 8.5 Color Review

Record final exact values in the brand reference document.

Check:

- sRGB export,
- no unintended embedded color profile conversion,
- green consistency across PNG and SVG,
- amber consistency across web and mobile,
- no semantic collision where amber appears to mean warning or payment,
- accessible adjacent text contrast; the logo itself is not a substitute for
  accessible text.

## 9. Technical Validation

### 9.1 Asset Validation

Add a deterministic validation step that checks:

- expected files exist,
- exact pixel dimensions,
- expected alpha presence or absence,
- square aspect ratio where required,
- Play icon file size is at most `1024 KB`,
- SVG files have valid `viewBox` values,
- no SVG references external fonts, URLs, or raster files,
- notification icon contains only the intended monochrome alpha shape.

### 9.2 Web Validation

Before declaring web integration complete:

- run brand export,
- run web typecheck and build,
- inspect favicon links,
- inspect manifest icon declarations,
- inspect Open Graph image URL,
- verify service-worker cache replacement,
- verify desktop landing, mobile landing, login, support, legal, and
  authenticated shell branding,
- verify regular browser and installed PWA behavior.

Use the canonical domain only during deployment verification:

```text
https://hypofit.bukae.co.kr
```

Git push alone does not deploy Vercel. Deploy only when explicitly requested.

### 9.3 Mobile Validation

Before declaring mobile integration complete:

- run mobile typecheck,
- run Expo config inspection,
- create local native builds,
- verify iOS Home Screen, Spotlight/search, Settings, splash, auth, and home,
- verify Android launcher masks, themed icon, splash, auth, home, notification
  shade, and status-bar glyph,
- verify no icon file is unintentionally missing from the build archive,
- verify app version/build numbers are changed only as part of an actual upload.

Do not use EAS cloud build while the current repository rule keeps it disabled.
Use local builds. Delete uploaded local IPA/AAB artifacts after upload is
verified, following the repository release rule.

## 10. Store And Release Workflow

Recommended rollout order:

1. Approve vector geometry and final colors.
2. Export and review the in-product mark and horizontal wordmark.
3. Export iOS icon, Android adaptive/monochrome/legacy icons, notification icon,
   and splash assets.
4. Apply and test native mobile assets in local builds.
5. Export web favicon, PWA, Apple touch, and social assets.
6. Apply and test web/PWA assets, including service-worker migration.
7. Export final App Store and Google Play upload icons.
8. Verify store-upload files against current console constraints.
9. Update landing/store creative templates to use the new identity.
10. Update reference documentation and close this plan.

Do not submit an iOS build or upload a new Play listing icon before the
corresponding binary uses the same identity. Store listing and installed-app
icon mismatches make the release look unfinished and can confuse review.

## 13. Explicit Non-Goals

This plan does not:

- rename Hypofit,
- redesign the entire UI palette,
- add animated logos,
- add alternate user-selectable app icons,
- migrate Expo SDK solely for Icon Composer,
- create a mascot,
- add a speech bubble or checkmark back into the mark,
- promise payment, verification, or matching guarantees through iconography,
- retain every AI-generated intermediate image in the repository.
